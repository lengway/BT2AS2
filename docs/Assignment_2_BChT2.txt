PART 2 — AMM (Automated Market Maker) Development


Task 3: Build a Constant Product AMM
Implement a fully functional AMM smart contract based on the constant product formula x * y = k.
Smart Contract Requirements:
 Accept two ERC-20 tokens as a trading pair
 addLiquidity(): users deposit both tokens proportionally, receive LP tokens
 removeLiquidity(): burn LP tokens, receive back proportional amounts of both tokens
 swap(): swap one token for another with 0.3% fee
 Implement getAmountOut() using the constant product formula
 Emit events for all operations: LiquidityAdded, LiquidityRemoved, Swap
 Implement slippage protection (minimum output amount parameter)
Testing Requirements (at least 15 test cases):
 Add liquidity (first provider and subsequent providers)
 Remove liquidity (partial and full)
 Swap both directions (tokenA → tokenB and tokenB → tokenA)
 Verify k remains constant (or increases due to fees) after swaps
 Slippage protection: test that swaps revert when output is below minimum
 Edge cases: zero amounts, single-sided liquidity, large swaps causing high price impact
 Fuzz test the swap function
Deliverables:
 AMM.sol, LPToken.sol, two ERC-20 token contracts
 Complete test suite with all tests passing
 Gas report for all AMM operations
Task 4: AMM Mathematical Analysis
Write a technical document (2–3 pages) analyzing:
 Derivation of the constant product formula and why it works
 How the 0.3% fee affects the invariant k over time
 Impermanent loss: derive the formula, calculate IL for a 2x price change
 Price impact as a function of trade size relative to pool reserves
 Compare your AMM to Uniswap V2 — what features are missing?


PART 3 — Lending Protocol Simulation
Task 5: Build a Basic Lending Pool
Implement a simplified lending/borrowing protocol.
Smart Contract Requirements:
 deposit(): users deposit ERC-20 tokens as collateral
 borrow(): users borrow against their collateral (max 75% LTV — Loan-to-Value ratio)
 repay(): users repay borrowed amount
 withdraw(): users withdraw collateral (only if health factor > 1)
 liquidate(): anyone can liquidate undercollateralized positions
 Track user positions: deposited, borrowed, health factor
 Implement a simple linear interest rate model
Testing Requirements (at least 10 test cases):
 Deposit and withdrawal flow
 Borrow within and exceeding LTV limits
 Repayment (partial and full)
 Liquidation scenario: simulate price drop, verify liquidation works
 Interest accrual over time (use vm.warp in Foundry)
 Edge cases: borrow with zero collateral, withdraw while having outstanding debt
Deliverables:
 LendingPool.sol with all functions
 Complete test suite
 Gas report
 Workflow diagram (draw.io or similar) showing deposit → borrow → repay → withdraw flow
